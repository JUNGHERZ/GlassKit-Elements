Theming

Set data-theme on the <html> element. All components sync automatically via a shared MutationObserver.

<html data-theme="dark"> <!-- or "light" --> <script> // Toggle theme const theme = document.documentElement.getAttribute('data-theme'); document.documentElement.setAttribute('data-theme', theme === 'dark' ? 'light' : 'dark'); </script>

Token defaults and color-scheme. The elements put GlassKit’s token defaults on the document once, in @layer glasskit-defaults, so any stylesheet of yours wins over them. Since 1.20.0 that layer carries the --gl-* tokens only. color-scheme stays off the page: each element sets it on its own theme wrapper, so a select’s list, a date picker or a scrollbar inside an element matches its theme while the page keeps its own. Before, importing the elements switched the whole page to color-scheme: dark — text without a colour of its own turned white, links light blue, native controls dark.

The token names stay global, so a component of yours that reads var(--gl-…, fallback) gets GlassKit’s value. A page that declares the tokens itself, or wants them on part of the page only, switches the defaults off — the attribute is watched, so it may also come or go later:

<html data-glk-defaults="off">

The elements then take the tokens from wherever they inherit them: glasskit.css, or a block of your own on a container around them.

Density

For admin screens, desktop layouts and narrow forms, data-density="compact" on the <html> element makes every control denser: fields and buttons 40px high instead of 52 and 56, smaller toggles, checkboxes and radios, denser list rows and modal actions. The sizes are GlassKit's density tokens (GlassKit 1.21.0), so they reach every shadow root by inheritance — a project's own values too; with data-glk-defaults="off" the preset comes from glasskit.css on the page, like every other token. The same observer mirrors the attribute onto each element's theme wrapper, so switching at runtime needs nothing else.

<html data-theme="dark" data-density="compact"> <script> // Back to the default density document.documentElement.removeAttribute('data-density'); </script>

Solid and tint surfaces

Not every screen wants glass. data-surface="solid" on the <html> element makes every surface opaque and turns blur and gloss off — cards, fields, buttons, lists, sheets — each in the colour the glass shows over the theme’s middle background. It is GlassKit’s solid surface preset (GlassKit 1.24.0): tokens only, so it reaches every shadow root by inheritance, and a project’s own values do too; with data-glk-defaults="off" it comes from glasskit.css on the page. Since 1.24.0 the observer mirrors this attribute onto each element’s theme wrapper as well, so a rule keyed on it matches inside the shadow roots.

<html data-theme="dark" data-surface="solid">

On a page with a background of its own — a brand colour, a photo — data-surface="tint" (GlassKit 1.25.0) makes the surfaces in the flow see-through tints of the text colour instead, nothing blurred. What lies over other content keeps the solid values, inside the shadow roots too: the panels of <glk-modal>, <glk-sheet>, <glk-popover>, <glk-toast> and the tab bars, with the fields inside them, and the secondary button. The wrapper mirrors this value like any other.

Primary as text

GlassKit 1.26.0 gives the primary a second token: --gl-color-primary fills, --gl-color-primary-text colours text and line icons on the page or the glass. In the elements that is the icon and label of the active <glk-tab-item>, <glk-list-item variant="accent">, the value of <glk-range>, the primary action of <glk-modal>, and the trigger under the pointer and the chevron of an open <glk-accordion-item>. It defaults to the primary. A brand that darkens its primary for white button text lightens the text in its dark theme, and the buttons keep their colour; the token reaches every shadow root by inheritance. Write the light rule after the dark one, because :root matches a page in the light theme too:

:root, [data-theme='dark'] { --gl-color-primary-text: color-mix(in srgb, var(--gl-color-primary) 18%, #ffffff); } [data-theme='light'] { --gl-color-primary-text: var(--gl-color-primary); }

--gl-tab-bar-active-color colours the icon and label of the active tab alone, for a spotlight that needs a lighter tone still; unset, they take --gl-color-primary-text.

Accent fills

White text on GlassKit’s orange reads 2.0 to 3.8:1 where the accent fills a surface: the primary <glk-button>, the chosen day of <glk-calendar> and <glk-date-strip>, the number of the current step in <glk-steps>. GlassKit 1.32.0 gives these fills tokens of their own, unset by default, so nothing changes until a project sets them: --gl-btn-primary-bg replaces the whole background of the primary button (today’s gradient when unset), --gl-color-primary-fill fills the chosen days and the current step (the primary when unset). A brand that keeps white text darkens the fills and leaves its primary alone — the primary also draws focus rings, borders and the accent as text. The tokens reach every shadow root by inheritance; with these values white reads 5:1 or more on every fill, in both themes:

:root, [data-theme='dark'] { --gl-color-primary-fill: color-mix(in srgb, var(--gl-color-primary) 60%, #000); --gl-btn-primary-bg: linear-gradient(135deg, var(--gl-color-primary-fill), color-mix(in srgb, var(--gl-color-primary-dark) 60%, #000)); } [data-theme='light'] { --gl-color-primary-fill: color-mix(in srgb, var(--gl-color-primary) 70%, #000); --gl-btn-primary-bg: linear-gradient(135deg, var(--gl-color-primary-fill), color-mix(in srgb, var(--gl-color-primary-dark) 70%, #000)); }

A brand that turns to a dark ink instead sets --gl-color-on-primary. Since GlassKit 1.32.0 the dot of <glk-radio> follows it as the checkbox tick does; before, it stayed white on the same orange.

Printing

Print dialogs leave out background graphics by default. With GlassKit 1.21.1 the parts that carry a state keep their colours on paper — checkbox, radio, toggle, progress, the current step, the chosen day, the slider thumb, the tone dots — inside the elements as well. A dark page prints its light text and surfaces on white paper; a page meant for printing switches to the light theme for it, and the elements follow:

let printTheme = null; addEventListener('beforeprint', () => { printTheme = document.documentElement.getAttribute('data-theme'); document.documentElement.setAttribute('data-theme', 'light'); }); addEventListener('afterprint', () => { if (printTheme) document.documentElement.setAttribute('data-theme', printTheme); else document.documentElement.removeAttribute('data-theme'); });

Form Integration

All form components participate in native forms via ElementInternals: their value goes into FormData, and a reset restores it. Since 1.20.0 the form also learns whether they are valid. The inner field checks required, pattern, min, type="email" and the like, and the element reports its verdict: form.checkValidity() is false while a required field is empty, a submit stops at the first invalid field with the browser’s own message, reportValidity() focuses it, and validity, validationMessage and willValidate answer on the element. <glk-button type="submit"> submits its form and type="reset" resets it — before 1.20.0 both did nothing.

Labels are tied to their fields: a screen reader names the field by its label, and a click on the label text focuses it — as do element.focus() and a click on a <label for> that names the element. The hint of <glk-input> is read as the field’s description.

Disabled (since 1.22.3): every form element follows its own disabled and a <fieldset disabled> around it, as native controls do — dimmed, out of the tab order, no input, a submit button sends nothing, and FormData leaves it out. Before, a fieldset reached only the form data: the fields inside stayed usable, and a submit button sent the form empty. The disabled property reflects the attribute, as on a native control.

<form id="settings"> <glk-input name="username" label="Username"></glk-input> <glk-toggle name="notify" label="Notifications" checked></glk-toggle> <glk-button variant="primary" type="submit">Save</glk-button> </form> <script> document.getElementById('settings').addEventListener('submit', (e) => { e.preventDefault(); const data = new FormData(e.target); console.log(Object.fromEntries(data)); // { username: "...", notify: "on" } }); </script>

Since GlassKit 1.31.0 every button keeps room beside its label, 24 px unless --gl-btn-padding-x sets another: a small button that takes its width from its text, in a row or an empty state, touched the text with its edges before. --gl-btn-radius rounds the buttons alone — 9999px for pill-shaped ones — and leaves lists and the segmented control as they are.

type="submit" submits the form the element sits in, type="reset" resets it — once the click has finished bubbling, so a listener that calls preventDefault() on the click stops it, as on a native button. Slots (since 1.22.0): prefix and suffix put an icon, a currency, a unit or a button inside the field’s box, at its start and end — right to left they swap sides. Row actions. Cells with class="glass-table__actions" stay at the row’s end while the table scrolls sideways, on a surface of their own: a <glk-menu>, or icon buttons with a <glk-tooltip>. The wrap’s edges shade where more columns wait. Sort buttons and row actions are in the Tab order; there is no grid navigation with arrow keys.

Empty. While the body has no rows, the slot="empty" content — a <glk-empty> — shows below the header. Cards. Below list-below the element copies each header’s text into its column’s cells as data-label, and GlassKit shows it before the value; the actions move to the card’s top end, numbers keep their tabular figures. The header stays for assistive technology, hidden from view, and the table’s roles are set explicitly, so a screen reader still meets a table.

Events: glk-table-sort. Properties: sort, direction, stickyHeader, listBelow. Slots: default (the table), empty. Parts: wrap (the scroller), empty. GlassKit’s tokens reach the table: --gl-table-max-height, --gl-table-header-bg, --gl-table-cell-padding (9px 10px) and --gl-table-header-padding (8px 10px).

Sorting by drag and drop

sortable on <glk-list> or <glk-tree> lets the visitor reorder the items (since 1.32.0): with mouse and pen after a few pixels, by touch after a long press of 500 ms — before it a swipe scrolls the page —, and with the keyboard. A raised copy follows the pointer, a line shows where the item lands, an item that takes it inside lights up, and the others glide out of the way. Lists with the same group exchange items, and so do trees, but a list never with a tree; breadcrumbs of that group take items from both. Without a group a list or a tree keeps its items to itself, and breadcrumbs with drop-target and no group still take them. Items with container — in a tree also items with children — take others inside them; in a tree a closed one opens after a moment under the dragged item. Keyboard: Space on an item picks it up, also where it has a handle (in a tree Enter still selects). Up and Down move it, Home and End to the ends; Right moves it into the item above, if that one takes items, Left out to the level above — from the top level onto the crumb of the level above —, both mirrored right to left. Space drops it, and the focus stays on it; Escape and Tab cancel. Every step is announced through a live region, and each item says how to move it.

In a shadow root (since 1.34.0): the item under the pointer is looked up in the root of each list or tree taking part, so a sortable list inside another element’s shadow root — the usual case in an app built of web components — takes drags by mouse and touch, and a group may span several roots. Until then only the keyboard sorted there. The folded levels of the “…” crumb take drops as well.

Items side by side (since 1.34.0) — the tiles of <glk-list grid>, or a layout of the page’s own — sort on the horizontal axis, mirrored right to left, with the line upright (GlassKit’s .is-sort-inline). Whether they stand side by side is read from the layout. The keyboard keeps the order of the items.

A sorter of the page’s own (since 1.34.0) uses the crumbs as drop targets too. dropTargetAt(x, y) on <glk-breadcrumbs> returns { item, index, current } for the crumb at a point of the viewport — item is its <glk-breadcrumb>, a folded level while the “…” menu is open —, { overflow: true } over “…”, or null. markDrop(target, { refused }) lights the crumb up while the drag is over it, or shows that it refuses the item; over “…” the menu opens after a moment, and markDrop(null) clears. The crumbs need drop-target or a group; the move on the drop is the page’s.

Events go to the element that owns the dragged item, each with via: 'mouse', 'touch' or 'keyboard'. glk-sort-start { item, from }; glk-sort-over { item, target, position } while the target changes, with position before, after or inside — cancelled, the target shows that it refuses the item, and a drop there does nothing; glk-sort { item, from, to, target, position } on the drop, cancelable and before anything moves, from and to as { container, index }; and glk-sort-cancel { item }, also for a drop back where the item came from. Not cancelled, the element moves the node itself; cancelled, the DOM is the page’s, which renders the new order from its state — the items glide into place either way. A drop on a crumb, or into a list’s container item, moves nothing: that level is not in the DOM, and the page moves the item there. The current crumb takes no drop from a list, since it stands for the list’s own level. If the page removes an item while it is dragged, the drag is cancelled.

Property messages on the list or tree translates the announcements: roleDescription and instructions are texts; pickedUp, moved, into, onto, dropped and cancelled are functions that get the label, the position, the size and the container. It applies at once, also to a list or tree that is sortable already. --gl-sort-duration (180 ms) and --gl-sort-easing (ease-out) time the glide; under prefers-reduced-motion nothing glides.

Build your own element

Since 1.14.0 the base classes are exported. A project element that extends GlkElement gets what every <glk-*> has: an open shadow root with GlassKit's stylesheet adopted (so .glass-btn & Co. work inside), the theme wrapper that follows data-theme and data-density, listeners re-armed when the element moves, and emit() for bubbling, composed events. GlkFormElement adds ElementInternals for native form participation. Try it — this button is a <demo-counter> defined on this page:

Building a complete website?

GlassKit Elements is the app layer of the GlassKit family – web components for application UIs.
